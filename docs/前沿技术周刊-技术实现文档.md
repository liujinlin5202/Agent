## 2. 数据源与解析（sources/ 抽象）

### 2.1 统一条目模型（items_json 每项）

```json
{
  "type": "news",                        // trending | news
  "title": "…", "url": "https://…",
  "source": "hacker-news",               // github-trending | hacker-news | sspai
  "author": "…",                          // 作者/用户名
  "published_at": "2026-08-30T10:00:00+08:00",   // 原文发布时间（必溯源）；trending 为 null
  "fetched_at": "2026-08-30T09:15:22",            // 本机爬取时间戳（每次抓取更新）
  "summary": "原文摘要…",                  // 原文自带摘要（RSS description 纯文本化）；无则 ""
  "ai_summary": null,                     // 预留字段（当前 AI 结果走 sanitize dict 直接供渲染，不回填条目）
  "confidence": null,                     // 预留字段，同上
  "trending": {"rank":1,"language":"Go","stars":1234,"today_stars":56}  // 仅 trending
}
```

旧数据兼容：读取时 `it.get("type","trending")`，`v1.x` 快照无需迁移即可被周报聚合。

### 2.2 三个源

| 源 | 端点 | 条数 | 要点 |
| --- | --- | --- | --- |
| github-trending | `github.com/trending?since=daily`（备源 api.github.com search） | 全量 25 行入库，渲染 Top15 | 沿用 v1.1 `fetcher.py`+`parser.py`；无 published_at（星榜客观数据） |
| hacker-news | 主：`https://hn.algolia.com/api/v1/search?tags=front_page`（单请求批量）；兜底：Firebase `topstories + item/{id}` | 前 15 条（有 url 且 score≥20；兜底通道上限 8 条） | Algolia 单请求 ~1.5s 且含 url/points/author/created_at；Firebase 每 id 1 请求（0.5 req/s 串行 ≈ 32s）→ 仅兜底；published_at = created_at/time（UTC）→ 转本地；author=by；summary=""（由 AI 摘要） |
| sspai | `https://sspai.com/feed`（RSS） | feed 全量（实测约 7 条） | 标准库 `xml.etree` 解析（零新依赖）；pubDate（RFC822）→ published_at；dc:creator→author；description 去 HTML 截 200 字→summary |

- 每源一个函数 `fetch_xxx(settings) -> list[Item]`，异常向外抛由调度层捕获：**单源失败 → 该源 0 条 + 计入自检数据，整体继续**。
- 源清单 `TECH_DIGEST_SOURCES`（默认 `github-trending,hacker-news,sspai`），可配置开关。

### 2.3 抓取预算

trending 1 + HN 1（Algolia 单请求；Firebase 兜底最多 8）+ sspai 1 ≈ 3 请求 × 2s 间隔 ≈ 10s + AI 15–30s（trending Top15 进 prompt 后略增） → 单次 daily ≈ 30s–1.5 分钟（红线 <5min，峰值内存不变）。

## 3. 数据模型（SQLite 迁移）

```sql
ALTER TABLE daily_snapshot ADD COLUMN issue_no INTEGER;      -- 期数
CREATE TABLE IF NOT EXISTS meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
-- meta 表键: issue_next（下一个期数, 缺省 1）、daily_posted:{date}（同日发帖幂等标记, 值=postID）
```

- `daily_snapshot.items_json` 改为多源混合数组（§2.1 模型）；旧数据保持兼容读取。
- 期数规则：daily 保存成功时在同一事务内 `issue_no = issue_next; issue_next += 1`（同日重跑走 `daily_exists` 短路，不跳号不重复发帖）。
- `weekly_report` / `run_log` 表结构不变；run_log 的 detail 增加 per-source 统计（计数/去重剔除/失败原因）。

## 4. 去重（dedup.py）

| 规则 | 实现 |
| --- | --- |
| URL 规范化 | 去 hash、去 `utm_*/ref/from/spm` 参数、host/路径小写、去尾 `/` |
| 标题相似 | `difflib.SequenceMatcher.ratio >= 0.85` |
| 判别 | 规范化 URL 相同 **或** 标题相似 → 重复（剔除） |
| 比对窗口 | **近 7 期** daily_snapshot（滚动） |
| 记录 | 日志写明每条被哪期剔除（去重透明度），日报内声明"与近 7 期对比剔除 N 条" |

## 5. AI 日报（daily_ai.py）

- **输入**：news 候选（每源 top 12，总上限 20，sspai 优先）+ **trending Top15**（生成中文简介的素材）。
- **AI 双通道**（`llm.py`，2026-09-01 上线）：主通道 market-deploy（OpenAI 兼容，`reasoning_effort=none` 防 504）→ 失败（非 200/网络异常/空响应）自动切备用通道 DeepSeek `deepseek-v4-flash-vision-exp`（Anthropic Messages 兼容端点 `api.deepseek.com/anthropic`，`thinking:{"type":"disabled"}`——该模型默认开思考，大 prompt 下 4096 token 会被 thinking 块烧光导致 text 为空）。任一通道 key 配置即启用 AI；两通道全败→降级。背景：平台 AI 网关 frp 链路故障（带 Bearer 请求被转发到远端网关时 http 打 https 端口稳定 400），修复周期不可控。
- **1 次调用**，输出严格 JSON（prompt 内给 schema 和"禁止编造"约束）：

```json
{"theme": "一句话主题 ≤30 字",
 "focus_title": "焦点条目标题（须与候选逐字一致）",
 "focus_depth": "150–300 字解读",
 "summaries": [{"title": "候选标题（逐字一致）", "title_zh": "英文标题的中文译名",
                "summary": "1–2 句", "confidence": "high|medium|low"}],
 "pending_titles": ["候选标题"],          // 没把握但重要（不展示，仅内部跟踪）
 "trending_desc": {"owner/repo": "≤30 字中文一句话简介"}}
```

- **标题精确绑定（2026-08-30 实测校准）**：初版用「编号 index」让模型写摘要，qwen3.8-27b 对长列表编号记忆不可靠（摘要与条目全面错位）→ 改为**标题绑定**：输出用 `focus_title`/`summaries[].title`，校验时按小写标题精确匹配候选（剥《》/引号包裹），写错或不存在的条目一律丢弃。
- **内容相关性校验**：模型即使标题写对，仍会把 A 条内容写进 B 条摘要 → 标题锚定后再校验摘要/深度确实在讲本条（标题英文词元词边界 / 标题中文 2-gram ≥2 / 原文摘要中文 2-gram ≥2，三路任一命中）；失败同样丢弃（宁缺毋滥）。
- **title_zh**：英文标题的中文译名（含中文才有效；中文原题忽略）；速览/焦点显示优先译名，缺失回退原文。
- **trending_desc**：key 按项目全名归一化匹配（剥 github url 前缀、小写），value 须含中文；无效条目丢弃 → 星榜回退英文简介。
- **解析容错**：剥 ```json fence → json.loads → 逐字段校验；失败→整次降级（原文直出）。
- **降级**（AI 失败/解析失败/key 缺失）：news 条目摘要直接展示原文 summary（无则显示链接），标注 `AI 未参与`；焦点区显示"今日无 AI 解读"。
- **置信度落地（2026-08-30 用户决策：待人工确认区删除）**：🟢(high)/🟡(medium) 进速览（🟡 排后）；🔴(low) 或 pending 的条目**整体不展示**（数据仍在库中，周报聚合不受影响），页脚注明"把握不足的条目不展示"。

## 6. 日报渲染（digest.py 重写，可读性 v2）

```text
# 📊 Tech Digest #1 · 2026-08-30 · 智谱开源 GLM-5.3-Flash 原生多模态模型

> 📅 2026-08-30（周日）｜ ⏱️ 18:39:30 生成 ｜ 🔍 主题：xxx ｜ ⚡ 抓取 7.4s
> 📡 数据透明：3 个站点 / 抓取 41 条 → 去重后收录 38 条（剔除重复 0 条）｜ 🤖 AI 已参与

## 🔥 今日焦点
### [标题(英文焦点显示中文译名)](url)
> 来源：少数派 · 作者：xxx ｜ 原文发布于 2026-08-28 08:29 ｜ 本机爬取 18:37:02
（150–300 字）

## 📊 GitHub 每日星榜          （奖牌+今日之星表格, Top15）
| # | 项目 | 语言 | ⭐ 总数 | 今日 ⭐ | 中文简介 |    ← AI trending_desc，缺失回退英文

## ⚡ 速览（N 条）
1. **标题(中文译名优先)** — 来源 · 8/28 · [原文](url)
  > 🟢 AI 摘要 1–2 句
2. …（2 行/条紧凑格式）

---
*本文与近 7 期按 URL/标题去重，剔除 N 条；置信度 🟢高 🟡中（把握不足的条目不展示）；只做改写摘要+链接，未搬运原文。*
> 本帖由爬虫 + LLM 自动生成，摘要可能有误，请以原文为准。
```

- 期数/日期/主题/透明度四要素全部在头部（硬性）；**H1 追加今日头条**（`headline_of`：优先焦点中文译名 → 焦点原题（须含中文，纯英文跳过——30 字发帖标题硬截断英文很难看）→ 兜底主题；自动剥「派早报：」类前缀与「等/…」尾缀，>32 字截断加 …）。
- **发帖标题**：`M/D 头条内容`（如 `8/30 智谱开源GLM-5.3-Flash原生多模态模型`），后端 30 字上限——超长先压掉头条内空格保完整，仍超长才硬截断（`main._daily_post_title`）；期号只保留在正文 H1。
- **速览行 2 行紧凑**（信息密度）：标题（译名优先）+ 来源·M/D·链接并入首行，第二行摘要；不再展示作者/本机爬取时间（溯源信息保留在焦点区 provenance 行）。
- **「⏳ 待人工确认」区已删除**（2026-08-30 用户决策）：AI 没把握的条目（🔴/pending）不展示。
- 周报引用日报时标题标注"（见 8/31 日报）"——由周报 AI prompt 传入每条的**起始出现日期**达成。

## 7. 五段式周报（weekly.py，v4.5 改版）

| 段 | 生成 | 说明 |
| --- | --- | --- |
| ① 本周回顾 | **AI 调用 1** | 输入：本周 news 聚合（跨天去重后 top 20，含出现天数/起始日期）+ trending 聚合摘要 → 输出 ①（5–8 件事按 AI 工具/前端/后端/安全 归类叙事，引用带 `（见 M/D 日报）`，**不允许复制日报焦点原文**）+ ③（3 条回看+一句话）+ ④（下周前瞻，标注"预计"）。v4.5：prompt 加信息价值硬性规则（重大发布/新范式/安全事件/影响开发者工作流优先；营销稿/小版本更新不选；每条讲清"为什么值得关注"） |
| ② 深度长文 | **AI 调用 2** | 输入：周内 top8 候选（v4.5: 5→8）→ AI 按信息价值择优写 1–2 篇 ×500–1000 字（背景+影响推演；候选平淡只写 1 篇）；失败→该段降级注释 |
| ③ 精选回看 | AI 调用 1 附带 | 3 条 + 一句话（规则：取 days+关注度 top 且未进深度长文） |
| ④ 下周前瞻 | AI 调用 1 附带 | 基于本周信号+已知日历，标注"预计" |
| ⑤ GitHub 星榜 | 程序 + **AI 调用 3** | 周聚合 Top10，**两行列表**（手机友好）：`N. **[repo](url)** — AI 中文简介` + 缩进次行 `语言 ｜ ⭐ 总数 · 本周 +增长`；简介复用 `ai_trending_desc`（送 12 条候选），失败回退英文 desc。v4.5 排在周报最末（"star 可以排后面"） |

- **v4.5 裁撤**（2026-09-21 用户决策）：②旧趋势分析的「每日收录量 ASCII 条形图」「语言分布 Top5」与「⑥ 爬虫自检」（run_log 统计 + HEAD 链接抽查）——手机端表格渲染成黑块/截断、失效链接清单对读者无信息量；`generate_weekly_md(days, week_label)` 签名随之去掉 logs/check_fn 参数。
- 标题：`# 🚀 前沿技术周报 · 2026-W36`；发帖标题 30 字内：`前沿技术周报 · 2026-W36`。
- 聚合逻辑：news 按 URL 去重（跨天），保留 days/最早日期/摘要合集；trending 沿用 v1.1 `aggregate()`。
- 渲染护栏：星榜末行与页脚 `---` 之间必须空行（否则次行被 CommonMark 解析成 setext H2）。

## 8. 调度与部署

| 项 | v1.1 | v2.0 |
| --- | --- | --- |
| daily | `*-*-* 09:15` | 不变 |
| weekly | `Sat *-*-* 10:00` | **`Sun *-*-* 10:00`**（改 unit 文件 OnCalendar 后 daemon-reload；旧 Sat 单元删除，避免双触发） |

- daily 任务末尾新增发帖步骤（当天成功即发公开帖；`run_log` 记 postID；发帖失败重试 1 次→`degraded=publish`）。
- **发帖目标地址自愈（2026-09-02）**：集市 Go 后端容器无宿主机端口映射，只能走容器 IP，平台侧重启 docker 后 IP 会漂移（实测 09-02：172.18.0.5→172.18.0.6，硬编码 IP 致当天发帖失败）。`publisher._base()` 现每次经 `docker inspect server` 动态解析，与配置不符即更新内存并原子回写 .env 的 `MARKET_BASE_URL`；仅当配置指向 docker 网段（172.16-31）时生效，显式域名/127.0.0.1 不动。
- 两个 service 均设 `TimeoutStartSec=600`（默认 90s 会杀掉 2 次 AI 调用的 weekly）。
- 其余单位/日志/门控不变。

## 9. 容错与降级矩阵（v2.0 增量)

| 故障 | 行为 | status |
| --- | --- | --- |
| 单源抓取失败 | 该源 0 条，其余照常；透明度如实显示 | `degraded`（detail: 源名） |
| 全部源失败 | 不产出日报（避免空转贴），记日志 | `error` |
| AI 日报失败 | 原文摘要直出 + 标注 AI 未参与，照常发帖（透明） | `degraded`（detail: ai） |
| AI JSON 解析失败 | 同上降级 | `degraded`（detail: ai_parse） |
| 发帖失败（日报/周报） | 重试 1 次 → 落盘不发 | `degraded`（detail: publish） |
| 期数/去重异常 | 期数读取失败→从快照行数+1 保守推导；去重失败→历史为空(仅当日内去重) | 日志告警 |
| 同一源链接永久失效 | 周报⑥ HEAD 抽查统计，不阻断 | 数据段如实显示 |

## 附录 A · 现行结构（v3 / v3.1，2026-09-14 定稿）

### A.1 日报正文结构（render_daily）

```text
开场钩子（AI，≤40 字，必须点名首条主体；不合格用兜底开场）
**1｜小标题(≤20字)** → 正文(≤120字，含「跟学生有什么关系」) → [原文](url)   ×3-4 条
```

### A.2 折叠星榜（`_star_details`，2026-09-14）

- 裸 HTML 直出。依据：集市前端 `MarkdownContainer-dG16P_xa.js` 实证
  `new MarkdownIt({html:!0,breaks:!0,linkify:!0,typographer:!0,xhtmlOut:!0})`；
  后端不转义（存量 461 帖含原始 `<img>`，转义为 0）。
- 收起态：summary 里露出前 3 条（`max-height:150px` + `mask-image: linear-gradient`），
  渐隐用 mask 而非白色渐变条——不赌帖子背景色。
- 展开态：首行 `<style>details.star[open] .star-pv,.star-hint{display:none}</style>`
  藏掉预览与「展开」提示；CSP 若拦 `<style>`，最坏 = 展开时前 3 条重复一次，不炸版。
- **块内禁止空行**：markdown-it 的 html_block 遇空行即止，空行会把块撕成 markdown 再渲染。
- 简介截 60 字、全量 HTML 转义（`html.escape`）；AI 中文简介优先，英文原简介兜底。
- 表格彻底弃用：旧 6 列表格在 390px 溢出 +204px，4 列版 +43px，列表式 0 溢出。

### B.2 渲染契约（render_repost）

- `pick = {item, why, lead, lead_kind: full|digest|summary|none, author, glossary}`。

- **长文收起**：full 态 >3500 字 → 前 1200 字预览 + `<details class="td-fold">`；
  收起态「📖 查看更多（全文约 N 字）」/ 展开态「⬆️ 收起」（td-fold 作用域样式切换，
  `<style>` 块全帖唯一；集市剥样式则标签并排降级）。总预算 FULL_CAP=8000，超出截断注明。
- **代码块保护**：翻译提示词强制「``` 围栏原样保留，一字不改不译，不许改写成文字或删掉」
  （09-18 事故：加粗版重译把原文 9 个 SQL 代码块全删了）；`_para_cut` 围栏感知，
  截断处 ``` 不配对则回退到围栏前。代码块横向溢出不处理（overflow-x 滚动即可）。
- **v4.4 布局（09-18 taste+impeccable layout，用户已批）**：仍单 `<style>` 块 td-* 作用域、
  剥样式全降级——编者按 `td-note` 浅灰面板（AI 加粗经 `_bold_html` 转 `<strong>`+HTML 转义）；
  名词卡 `td-fold td-gloss` 卡片容器（保留原生三角）；文章折叠 summary 描边胶囊
