## 1. 背景与目标

### 1.1 背景

站长（用户本人）持续输出技术内容，形成「**Tech Digest**」刊物：每日一期日报（30 秒扫完、5 分钟读完），每周日一份周报（深度总结）。与 sse_market_assist 的被动应答互补。

### 1.2 目标（阶段演进）

| 阶段 | 内容 | 说明 |
| --- | --- | --- |
| **M1（MVP，已上线）** | 每日 GitHub Star 排行榜 | 已实现并验证（v1.0） |
| **M2（周报+发帖，已验证）** | 周末 AI 周报 + 自动发布 | 已实现；真实私密帖 #5725 验证通过（v1.0→v2.0 过渡） |
| **M3（v2.0 核心）** | **多源日报**（星榜 + 要闻速览 + 焦点深度） | 本文档验收对象 |
| **M4（v2.0 核心）** | **六段式周报**（回顾/趋势/深度/回看/前瞻/自检） | 改周日 10:00 |
| M5（可选） | 每日榜推送渠道（Telegram/邮件）、图表升级 | 待定 |

### 1.3 设计红线（沿用 v1.0，全部保留）

1. **零常驻进程**：systemd timer 触发，任务跑完即退。
2. **零耦合**：独立目录/venv/配置，与现有服务互不读取、互不修改。
3. **磁盘受控**：不存原始 HTML，只存提炼数据（SQLite + markdown），月增 ≤ 5MB（多源后上调，仍远低于风险线）。
4. **AI 通道独立**：market-deploy 网关（`qwen3.8-27b-awq`、temperature 0.2、max_tokens 4096、`reasoning_effort=none`）；**不使用 DeepSeek**。
5. **失败静默降级**：单源失败不影响整体；AI 失败降级（日报=用原文摘要直出+标注；周报=数据版模板）；绝不抛错中断调度链。

## 2. 用户与使用场景

- **用户**：站长 1 人 + 集市读者（周报公开发布）。
- **场景 1（每日，周一~周日 09:15）**：打开集市/输出目录看日报：30 秒扫完速览，5 分钟读完焦点。
- **场景 2（周日 10:00）**：周报自动发布到集市技术分享分区。

## 3. 功能需求（FR）

### FR-1 每日日报（多源）

| 项 | 内容 |
| --- | --- |
| **数据源（首版）** | `github-trending`（已有）+ `hacker-news`（官方 API）+ `sspai` 少数派 RSS（中文）——**每源独立抓取，失败自动跳过并计入自检数据**，源清单可配置（`TECH_DIGEST_SOURCES`） |
| **期数** | `Tech Digest #N · 2026-08-31`，N 从 **#1**（首个发布日）开始自动递增（SQLite 计数，幂等：同日重跑不跳号） |
| **输出文件** | `output/2026-08-31-daily.md` |
| **结构（自上而下）** | ① 头部元信息：期数与日期、一句话今日主题总结、**数据透明度**（本次爬取 N 个站点/共 M 条、筛选后收录 K 条、去重剔除 D 条、AI 是否参与）② **焦点 1 条**：当日最有信息量的一条，150–300 字短深度（背景+变化点+价值判断）③ **GitHub 每日星榜**（v1.0 版块保留，奖牌+今日之星）④ **速览 3–5 条**：每条 1–2 句 + 链接 + 原文发布时间 ⑤ 去重记录+AI 声明+置信度说明（见下） |
| **每条溯源（硬性）** | 标题+原文链接（可点击）、来源站点与作者、**原文发布时间**（非爬取时间）、爬取时间戳（当日本次抓取）、摘要标注（AI 生成摘要 / 原文摘要） |
| **去重（硬性）** | 与**近 7 期**已发布内容按「URL 规范化」+「标题相似度（≥0.85 或 URL 相同即视为重复）」去重；**昨天发过的今天绝不再发**；帖内声明"本次剔除 N 条重复" |
| **置信度（硬性）** | 每条内容带置信度标记（🟢 高 / 🟡 中 / 🔴 低"待人工确认"）；AI 没把握的**宁可不选**，置信度低且重要的放入"待人工确认"区 |
| **质量护栏（硬性）** | 帖尾固定声明：`> 本帖由爬虫 + LLM 自动生成，摘要可能有误，请以原文为准`；只做改写摘要+链接，不整段搬运原文 |
| **AI 参与** | 1 次调用：给定候选集（各源 top N + 星榜前 3）→ 输出 JSON（焦点选题+短深度、每条一句话摘要、置信度、一句话主题总结）。AI 失败 → 降级：原文摘要直出 + 标注"AI 未参与"，焦点区标注"今日无 AI 解读" |
| **自动发布** | 与周报同链路：post 到集市**技术分享**分区（公开帖）；**同日幂等**（重跑不重发）；失败重试 ≤1 次 → `degraded=publish` 仅落盘；标题 `Tech Digest #N · YYYY-MM-DD` |

### FR-2 六段式周报（周日 10:00）

| 段 | 内容 | 生成方式 |
| --- | --- | --- |
| ① **本周回顾** | 本周最重要 5–8 件事，**按主题归类**（AI 工具 / 前端 / 后端 / 安全…）组织叙事线；引用标题时标注"（见 8/28 日报）"——**不复制日报焦点文字，重新组织** | AI（调用 1） |
| ② **趋势分析** | 7 天聚合视图：话题热度曲线（ASCII 条形图）、GitHub star 增长榜、语言分布变化 | 程序聚合（无 AI） |
| ③ **深度长文** | 本周挑 1–2 篇展开：完整背景 + 影响推演，500–1000 字 | AI（调用 2） |
| ④ **精选回看** | 本周最值得回看的 3 条（读者错过日报可补） | 程序选 top3 + AI 一句话 |
| ⑤ **下周前瞻** | 即将发生的：发版计划、会议、deadline（基于本周数据 + 已知日历推断，标注"预计"） | AI（调用 1 内附带） |
| ⑥ **爬虫自检数据** | 本周抓取量、收录率、去重率、链接失效数——"我们自己的数据也公开" | 程序（run_log/自检统计） |
| **硬性护栏** | 同日报：AI 生成声明、不改写原文、溯源完整、`（见 X 月 X 日日报）` 交叉引用 | — |
| **输出/发布** | `output/2026-W36-weekly.md`；自动发布集市「技术分享」分区（公开帖，默认 isPrivate=false） | — |

| 项 | 内容 |
| --- | --- |
| 表 | 沿用 `daily_snapshot` / `weekly_report` / `run_log`；`daily_snapshot.items_json` 存**多源混合条目**（每项含 type: trending/news、source、author、published_at、fetched_at、url、title、summary、confidence、ai_generated、star 字段（trending 专有）） |

- 沿用：market-deploy 三件套、MARKET_REFRESH_TOKEN/TELEPHONE/BASE_URL、TOP_N、阈值、目录、保留策略。

### FR-6 日志（扩展）

- 每源一行：源名、抓取条数、收录、去重剔除（含与哪期重复）、耗时、失败原因。
- 自检数据（周报 ⑥）从 run_log + 每日 run 统计汇总。

## 4. 验收标准（v2.0）

### 日报（M3）

1. 手动触发生成当日日报：头部含期数/日期/主题一句话/数据透明度；含焦点 1 条（150–300 字）+ 星榜 Top15 + 速览 ≥3 条。
2. **溯源完整**：每条含链接/来源/作者/原文发布时间/爬取时间戳/AI 摘要标注——抽查 ≥5 条一致。
3. **去重生效**：连续两天触发，第二天不含第一天的任何条目（按 URL/标题），帖内声明剔除 N 条。
4. **期数连续**：重跑同日不跳号；次日递增 1。
5. 单源故障：停掉一个源（配置删源）后其余源正常出报，帖内数据透明度如实显示。
6. AI 故障：模拟（断 key）后降级出报（原文摘要+标注 AI 未参与），任务 rc=0。
7. **日报自动发帖**：手动触发后集市技术分享分区出现新帖（公开），run_log 记录 postID；同日重跑不重发。
8. 零影响/磁盘/密钥隔离：沿用 v1.0 M1 验收标准。

### 周报（M4）

1. 周日 10:00 timer 触发（改为 Sun），`output/2026-Wxx-weekly.md` 含**六段**全结构。
2. ①本周回顾为**重新组织**的叙事线（主题归类），引用处带"（见 X/X 日报）"标注，无逐句复用日报焦点文字。
3. ②趋势分析含 ASCII 图表 + star 增长榜（7 天数据）。
4. ③深度长文 500–1000 字 ×1–2 篇。
5. ⑥自检数据与 run_log 一致。
6. 自动发布成功（公开帖），run_log 记录 postID；手动重跑同周不重复发帖。
7. AI 任一调用失败 → 对应段降级（回顾段=程序摘要列表；深度段=删除条目并注明），其余段正常。

## 5. 风险与对策（v2.0 新增）

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 新源可达性/结构变化（HN API、RSS 字段） | 中 | 每源独立 fail-open + 自检统计；RSS 解析用通用 feedparser 逻辑（或标准库 xml），不依赖第三方服务 |
| 去重误杀（同日多条同主题不同文） | 中 | URL 精确 + 标题相似度双阈值；正文相似度不参与；误杀率靠日志观察调整阈值 |
| AI 输出 JSON 解析失败 | 中 | prompt 要求严格 JSON + 解析容错（失败降级原文直出）；输出校验（焦点有 150-300 字等） |
| 日报每日发帖刷屏风险 | 中 | 评审已定：日报也发帖（公开）；频率 1 帖/日可控，发布质量靠护栏保证；如后续集市反馈不佳可切回"仅落盘"（一行配置） |
| 趋势图在集市渲染效果 | 低 | 用纯文本代码块/表格（markdown-it 通用），不用 mermaid（集市未启用） |
